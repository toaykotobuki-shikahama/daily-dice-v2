# 試行回数版：設計と既存への影響

## 調査した既存構成

お客様はGitHub Pages → transport.js → GASのiframe Bridge → publicApiのregister/status/rollを利用します。スタッフ確認は本番シートに紐づいた管理GASのGoogle認証付きダイアログです。authorize_はSessionの実アカウントメールとADMIN_EMAILSを照合します。管理GASを公開Webアプリにしません。

今回もこの認証を使用し、管理メニューにスタッフ検証画面を追加します。新しいパスワード・お客様側のログイン・一般公開のテストAPIは追加しません。実施者名は記入名、操作アカウントは実Googleアカウントです。カウンターの共用アカウントの場合、実施者名は自己申告です。

## 分離

試行版は別スプレッドシート「サイコロ検証専用DB_試行版」を作成し、TEST_TRIAL_SPREADSHEET_IDに保存します。旧検証のTEST_SPREADSHEET_IDとも分けます。本番SPREADSHEET_IDや旧検証IDとの一致、DB名の不一致、想定外シートへの書込を拒否します。実施IDはTEST-、試行IDはTRY-、カードイベントはTEST-ROLL-を使用。本番シートの参加者・日別履歴・スタッフログは変更しません。

管理GASの実行環境・Google利用枠は本番管理機能と共通です。DB分離だけでGoogleの割当まで独立するものではありません。公開GASは別プロジェクトですが同じ所有アカウントならアカウント単位の枠を共有する場合があります。上限を押し上げる自動負荷試験は実装していません。

## 試行の記録

1. armで試行ID・認可値・条件スナップショットを保存。この時点は未開始、回数0。
2. 共通ゲームの開始イベントをブラウザに保存。executeがGASへ到達すると開始イベントをサーバーにも記録。
3. 実際の出目／結果表示を共通ゲームの通知で受け取りfinishを自動送信。保存テストは保存後の再取得・復元表示まで行う。
4. 開始済みの成功・失敗・中断・未確認を各1回として計上。所感保存は加算しない。
5. 再アクセス時は前の未完了試行を復旧し未確認として閉じる。抽選を再実行しない。

通信到達前の開始は、試行に発行した認可値と実操作イベントの組で識別。ブラウザの記録も失われ、GASへの到達もない場合は開始の有無を判定できません。未開始として残り、推定の成功・回数を補いません。ログの未開始行もCSVに残します。

LockServiceで管理GAS内の更新を直列化します。開始・準備は要求ID、実操作は操作ID、終了は試行IDで再送を識別。同じ操作IDの再送はカードを更新しません。試行行の状態を正本とし、実施履歴への集計書込が遅れた場合も再取得で行のrevを照合します。Sheetsは複数行にまたがるDBトランザクションではないため、通信結果不明は明示し、復旧後に集計します。

## 懸念と運用条件

- スタッフは既存ADMIN_EMAILSで許可されたGoogleアカウントで操作します。新しいスタッフ専用の低権限ロールはありません。シート編集者はコードも編集できるため、信用する管理アカウントだけに権限を限定してください。
- 別権限のスタッフに管理シートを共有したくない場合は、本番から切り離した管理GAS＋検証DBを専用アカウントで用意し、テストファイルと共通コードを同じ版で管理する代替設計が必要です。今回の管理プロジェクトを一般公開して対応しないでください。
- 管理用シートのPC画面を入口とします。一般公開の独立したスタッフログインサイトは作成していません。スマートフォン実機でのタッチ・表示・Pages通信は別途実環境チェックが必要です。
- Aの認証項目は認証済み通信の確認です。Googleログインに要した時間を自動計測しません。不許可アカウントの拒否は管理者の受入チェックです。
- 同じ実施IDは1画面で使用してください。複数画面を開いた場合は復旧し、二重操作の防止記録を確認します。
- 本番の参加条件やキャンペーンはテスト開始に伴って変更しません。
