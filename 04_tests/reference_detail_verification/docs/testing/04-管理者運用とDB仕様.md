# 管理者用：試行記録・集計・CSV

## メニュー

本番シートの「サイコロ管理」→「スタッフ検証」から、専用画面、初期作成、マスタ更新、結果集計、サマリー更新、CSV、テスト停止／再開、テスト初期化を操作します。既存のスタッフ確認・集計・キャンペーン設定は維持します。

## 目標とテスト定義

テストマスタは16項目。重点6項目は通常100、タップ100、連打100、復元50、保存100、達成完了30の480回。認証、タイミング、異常操作など補助20回も有効な初期設定で、全項目の合計は500回です。A〜Eごとに実施を開始し、各実施にそのVerの目標を設定します。時間による完了条件はありません。

テストIDは固定で使用してください。特にB-04は0〜200ms未満／200〜650ms未満／650〜850msの3条件を順番に判定します。表示手順だけ変えて時間帯の自動判定を変えることはできず、その場合はコードの修正も必要です。目標・案内・条件・有効を変更したら「テストマスタ更新」。条件識別Verが再計算されます。実施開始時に全条件を固定するため、途中の実施は変更前の条件を保持します。

アプリ版が変わると古い実施の操作・再開を停止します。閲覧・所感・CSVは利用でき、新しい実施で再テストします。アプリ版識別はgame-source.jsonと画面に表示。

## 4シートと列

| シート | 主な内容 |
|---|---|
| テストマスタ | Ver、ID、順序、名前、操作種類、開始条件、手順、正常条件、計測開始／終了、目標、判定、中断扱い、定義Ver、有効 |
| テスト実施履歴 | 実施ID、実施者、Googleアカウント、開始／最終日時、アプリ／テストVer、目標、総数、成功／失敗／中断／未確認、状況、所感、固定計画、状態、操作履歴 |
| テスト操作ログ | 試行ID、実施ID、項目、番号、版、実施者、操作名、開始有無・根拠、開始／終了、各時間、通信回数、結果、エラー、端末／回線、所感・証拠、対応状況、要求ID、条件／状態／通信／計測JSON、認可値 |
| テスト検証サマリー | アプリ・Ver・ID・定義・条件・端末・回線別、回数、各結果、率、計測数、平均／中央値／最大／P95、通信／サーバー／演出平均、操作感、不具合件数、対応状態 |

全列の正確な構造はTestCore.gsのTRIAL_SCHEMAS_を参照。計画JSONなど機械用列は編集しません。JSONに文字が見えても、その中の回数を書き換えて運用しないでください。表の実施回数はログから再計算されます。

認証前操作や中断・再開そのものは実施履歴の操作履歴JSONに時刻を保存し、開始されなかった試行行は未開始として保持。結果集計で回数を同期します。開始済み試行は全結果を含めて実施数とします。通信中の未完了行は未確認です。

## 計測の読み方

| 計測 | 実測区間・制約 |
|---|---|
| 操作処理時間ms | 親画面のperformance時計で、開始イベントから結果表示まで。通常は出目表示、保存は再取得表示、達成は確認完了表示。計測値の送信・finish保存待ちは含まない |
| GAS往復時間ms | 実操作execute送信直前から応答受領までの合計。待機キューの時間は別のqueueWaitMsとしてJSONへ保存。arm/status/finish等の管理通信は含まない |
| GAS通信回数 | 試行の実操作要求数。二重再送を含む。管理用RPCや初期画面取得を含む全HTTP数ではない |
| GAS計測区間ms | GASの要求受付から認証、Lock待ち、読取、処理を経て操作ログ書込直前までの合計。最後のSheets書込、返却処理、ネットワークを含まない。GAS実行全体時間とは区別する |
| 演出時間ms | 通常回転開始から停止通知までの合計と、達成演出開始からMISSION文言表示までの合計。金色サイコロの表示後の回転継続・人が閉じるまでの時間は含まない |
| 計測JSON | タップ数／時刻、達成演出区間、時計の基準、キュー待ち、表示した出目・累計。通信JSONに操作ID、成功／エラー、サーバー区間、往復時間、再送回数 |

回転・通信は重なるため、区間を足して全体時間にしません。達成の操作全体時間には人が次のサイコロを押す間やコード入力をする時間も含まれます。Googleログイン所要時間、ブラウザ終了中の処理時間、通信結果不明時の全体時間は推測しません。欠測は空欄、集計で未取得と件数表示。実測0msは有効値です。

中断後に同じ試行の時計を継続しません。未完了試行を中断／未確認として閉じ、復旧後の新しい試行を計測します。そのため勤務をまたぐ中断時間は処理時間に入りません。

## サマリー・版比較

「テスト検証サマリー更新」で作り直します。最小単位はアプリVer＋テストVer＋項目＋定義Ver＋条件識別＋端末＋回線です。率の分母は開始済み全試行で、中断・未確認も分母に含みます。時間統計は実測値のみ。P95は昇順のceil(0.95×件数)番目、中央値は中央2値の平均です。

同じ端末・回線・定義Verでアプリ版だけが変わった行を並べて比較します。条件が違う行を混ぜて改善を断定しません。集計目標はその区分に記録がある実施ID数×項目目標です。1実施を複数端末で行った場合は区分別の参考達成率になるため、実施全体の完了判定は実施履歴を確認します。

対応状況は操作ログのプルダウン「未確認／確認中／修正済／再テスト待ち／完了」で管理。所感を正常に変えても自動失敗を成功へ上書きしません。回数達成・要確認は保持し、対応状況の更新と新しい実施の再テストで管理してください。

## CSV・証拠

CSV出力は詳細、サマリー、実施履歴、テスト定義の4ファイル。UTF-8 BOM付き、改行・カンマ・引用をエスケープし、式になる先頭文字を文字列として出力します。詳細は未開始行も含み、認可値は除外。ファイルをダウンロードして分析へ渡します。アカウントメール・実施者名が含まれるため、店の管理者が共有対象を確認してください。

画像は自動アップロードせず、店内指定のアクセス制限付きDrive等にスタッフが保存し、https共有URLを所感へ入力。コードはURL先を取得しません。公開フォルダを使わず、管理者が画像へのアクセス権を確認してください。

## 上限・停止・初期化

初期の安全上限は1実施2000試行／10000実操作要求、DB10000行・100実施。UI要求間隔3.2秒、GAS側2秒・1アカウント20回/分・管理GAS全体30回/分。無限自動試行はなく、手動で1試行ずつ開始。30秒で結果不明のタイムアウトを検知します。GASの実行をキャンセルできないため、遅れてサーバー確定する場合は復旧で照合します。

短時間の実操作失敗3回でサーバーが自動停止。UIも連続通信失敗3回で停止します。再取得で原因を確認してから再開します。管理者の「検証モードを停止」はarm/executeを止め、状態照会・記録終了は可能。本番抽選には影響しません。初期値はGAS最大能力を表す数値ではありません。

ログ全体の走査とSheets書込があるので、大量化すると遅くなります。CSV保管後、全員中断・検証停止で「テストデータ初期化」。確認欄に「試行テストだけ初期化」と入力。3記録シートを非表示バックアップした後に明細を消し、マスタ・本番・旧検証DBは残します。上限に達する前に保管・初期化してください。バックアップは管理者が保管方針を決めます。
