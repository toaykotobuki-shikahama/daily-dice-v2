# 移行・本番反映・切り戻し計画（未承認、実施禁止）

## 移行前に確定すること

- 管理・公開GASの実プロジェクトID、保存版と稼働版、WebアプリのデプロイID/実行者/公開範囲、接続ブックIDを管理者画面で照合する。
- 公開PagesのコミットとURL・LINE/POPの `source` パラメータ、管理権限、トリガー、旧設定マスタの列・日付型・IDを読み取り専用で保全する。
- `daily-dice.identity.v1`、参加者識別値、SERVER_KEY/secretの由来と継続性を安全な領域で照合する。鍵・秘密値をこのZIPや公開コードへ記載しない。
- 旧キャンペーンIDごとに移行/保留の根拠、カード・抽選・確認履歴の再構築結果、旧データ読み取り経路を記録する。旧DBの全体上書きは禁止。

## 本番切替（別途承認が出た後だけ）

1. T01〜T38、R01〜R10の該当確認、R05の競合・原子性・復元、切り戻しリハーサルを完了する。
2. 旧環境のソース・設定・マニフェスト・デプロイ・接続先・データ指紋を保存する。
3. 旧新の二重書込を止める手順と新規処理の一時制御を複製環境で再現し、固定URLと旧キャッシュ経路を確認する。
4. 責任者・実装担当が別々に承認した後、互換スキーマ→互換GAS→Pages→V2有効化の順に適用する。既存 `/exec` やGitHubはこのZIP作成では触れていない。
5. 起動・抽選・日別履歴・累計・当日終了・達成コード・スタッフ完了・集計を照合する。異常時は受付を止めて復旧へ移る。

## 切り戻し

1. まず安全停止し、時刻と確定済み操作を保全。
2. V2の受付を無効化し、必要なら検証済みの前バージョンへ戻す。
3. 旧Pagesと旧GASが互換する版に戻し、旧開催フラグを責任者判断で整える。
4. 確定済みの新規履歴・カード・確認成功を旧新両方で照合し、重複・欠落がないことを確認。
5. DB全体を古いバックアップで上書きせず、キーを再生成しない。復旧承認前に受付を再開しない。

この計画は実行済みの切替・切り戻しを意味しません。
