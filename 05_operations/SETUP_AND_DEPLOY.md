# 新規V2 隔離環境セットアップ

## 0. 対象

この手順は新規に作るV2試験環境向けです。既存管理スプレッドシート、既存GAS、既存GitHub Pagesのコード・設定・デプロイを変更しないでください。本番切替はこの手順の範囲外です。

## 1. Google環境を新規作成

1. 新規スプレッドシートを作り、管理用GASをそのブックに紐付けます。
2. 別プロジェクトとして新規公開GASを作成します。
3. スプレッドシートを別途複製して簡易テスト専用ブックを作ります。実データを含めません。
4. `02_gas/public/` のファイル一式を公開GASへ、`02_gas/admin/` のファイル一式を管理GASへ登録します。どちらにも `Domain.js` と `Repository.gs` を置きます（両側で同一。`npm test` の静的チェックで照合）。`Initialize.gs` は管理側にだけ置きます。
5. 各プロジェクトの `appsscript.json` を対応するディレクトリのものにします。Advanced Google Sheets Service (Sheets API v4) を有効にし、Cloud project側でSheets APIを有効化します。管理側では `UrlFetchApp` の外部リクエスト権限も承認します。
6. 両GASのScript Propertiesに同じ `DB_ID`（新規V2ブックID）と、同じ新規生成した長さ64文字以上の `ADMIN_RPC_SECRET` を設定します。管理側には確認済み個人アカウントの `ADMIN_EMAILS`、簡易テスト用の別ブックID `TEST_DB_ID` を設定します。公開側には `PUBLIC_ORIGIN=https://toaykotobuki-shikahama.github.io` を設定します。秘密値はコード・HTML・ログ・ZIPへ書かないでください。
7. 管理GASから `initializeV2Database()` を一度実行し、新規V2ブックにヘッダーが揃った全シートが作成されることを確認します。簡易テスト用ブックは初回操作時に専用シートを作成します。詳細検証用DBは管理メニュー「スタッフ検証 → テストマスタ初期作成」から新規生成し、V2 DB/簡易テストDBと異なることを確認します。
8. 新規公開GASを検証専用Webアプリとしてデプロイし、その `/exec` を管理側の `PUBLIC_EXEC_URL` に設定します。署名RPCの有効/無効認証を確認してから、開催設定を手動登録し、設定・版番号・操作者の監査を照合します。サンプルのDICE-IDや日程を本番値として登録しません。

## 2. 隔離デプロイ

1. 公開GASを新しいWebアプリとしてデプロイします。アクセス範囲は画面との疎通要件を満たす公開設定が必要ですが、URLを既存の固定URLへ向けないでください。
2. Apps Scriptが表示する承認スコープと実行アカウントを確認します。`ADMIN_RPC_SECRET` は両プロジェクトの非公開Script Propertiesだけに置き、Pages/HTML/JavaScript/ログに含めないことを確認します。
3. `03_pages/config.js` のプレースホルダーを試験用WebアプリURLにだけ置き換え、別の検証用Pagesブランチ/リポジトリで表示・通信を試します。既存 `daily-dice-challenge` へのpushは行いません。
4. PC、スマートフォン、LINE内ブラウザ相当、店内QR相当でT12〜T38の関連ケースを実施します。GASのエディタ実行だけで実機合格としません。
5. ローカルテストを再実行し、実行環境、日付、バージョン、ログ・画面証跡を記録します。

## 3. 必須停止条件

- HMAC署名RPC、単一公開GASの排他、設定/監査と抽選/停止/確認の一括保存・異常終了試験が未合格
- R01/R04の現行ID・配布元・データ移行一覧が未確認
- テストDBと本番相当DBのIDが一致、または区別できない
- 旧画面と新画面の二重書込防止・キャッシュ互換を未検証
- 12/1運用の現行安定版点検が未完了

いずれかに該当すれば、旧環境・本番への接続、Pages反映、参加受付切替を行いません。
